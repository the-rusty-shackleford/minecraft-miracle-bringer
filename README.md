# Miracle Bringer

Once in a while, a lethal blow is answered with a blessing. NeoForge 1.21.1.

## What it does

When a blow would take a player's last health -- from any cause: a mob, a
fall, lava, an arrow, another player, drowning, the void, a wither's touch --
there is a chance it is refused instead. Two percent by default, once a day
per player on the clock. When it comes:

- Health is restored in full, and ten golden hearts are granted that stay
  until spent.
- **Jesus' Blessing** is applied for ten seconds. Under it no damage lands
  and no harmful effect takes; any harm already on the player is cleared,
  fire put out, air refilled, freezing thawed, every tick.
- A visitor appears two and a half blocks in front of the player, facing
  them, with a halo turning slowly above his head, and hovers for the
  blessing. When it ends he rises, trailing light, and is gone in four
  seconds. Everyone nearby sees him.
- A chord sounds when the blessing arrives, a shimmer when he rises.

`/kill` still kills: it neither triggers the miracle nor is refused by the
blessing, so an operator's word is final. A totem of undying is only spent
when no miracle came.

Every number is in `config/miraclebringer-common.toml`:

| Key | Default | Meaning |
|---|---|---|
| `miracle.chance` | 0.02 | the chance a lethal blow is answered, 0 to 1 |
| `miracle.durationTicks` | 200 | how long the blessing lasts |
| `miracle.absorption` | 20.0 | golden hearts granted, in health points |
| `miracle.cooldownHours` | 24.0 | hours between a player's miracles; 0 for none |
| `miracle.killCommandExempt` | true | whether `/kill` keeps killing |

## How it decides

The game fires an event just before damage is applied, after armour and
enchantments have taken their share and before absorption has, so the
number there is what will come off absorption and health together. Every
cause of damage in the game passes through it; there is no other door. If
that number reaches the player's health plus absorption, the blow is
lethal; if the cooldown allows and the roll comes up, the damage is set to
zero there and the blessing applied. That runs before the game's own totem
check.

The blessing refuses damage in the first event the game fires for a blow,
and harmful effects as they are offered. Golden hearts are granted by
raising the max-absorption attribute with a modifier of this mod's, since
absorption is capped at zero unless something raises it and vanilla only
does so for as long as its own effect lasts.

The visitor is a mob with no mind: no AI, no gravity, no hunger for
anything. He cannot be hurt, pushed, leashed or clicked, and he is never
saved, so a world reloaded mid-visit has no visitor rather than one left
standing for ever. He is moved by position, because a mob with no mind
never runs the step that would apply a velocity.

## Provenance

The visitor's skin, `textures/entity/visitor.png`, is a player skin Rusty
chose from NameMC: <https://namemc.com/skin/ef9129259b19d66e>. NameMC
states no licence for the skins it hosts and names no author for this one.
It is used here as it was found; anyone publishing this mod more widely
should replace it or establish its terms. Everything else in the mod -- the
halo, the effect icon, the sounds -- is generated by `devtools/art/build.py`
and original.

## Building

```
./gradlew build
```

produces `build/libs/miraclebringer-<version>.jar`. No dependencies beyond
NeoForge.

## Testing

Three tiers. The first two run under `./gradlew check` (and so `build`).

- `./gradlew test` -- plain JUnit against the `domain` source set, the pure
  layer: lethality, the odds, the cooldown, what the blessing lets through,
  the visitor's movement. Compiled against nothing but the JDK. Partitions
  are written at the top of each test class.
- `./gradlew runGameTestServer` -- gametests on a real headless server, as a
  mod of their own, in batches the framework runs one after another because
  the chance is one config shared by every test running at once. With the
  chance certain: **every damage type the game registers** -- read from the
  registry, so any a mod adds is swept too -- is answered with the blessing,
  except the kill command; an explosion, a zombie's blow, an arrow and the
  kill command through the dispatcher are tried through their own code
  paths; the blessing refuses every damage type but the kill command, and
  every harmful effect; fire is put out and air refilled; the visitor
  appears before the player and rises when the blessing ends; a totem is
  not spent. With no chance: a lethal blow kills and a totem works. With a
  day's cooldown: the second miracle waits. Without the exemption: the kill
  command is answered too. **The server's exit code is not the assertion**
  -- it is zero when no test ran -- so the task reads the framework's
  "All N required tests passed" line and fails without it.
- `./gradlew runPhotoBooth` -- the end-to-end test, on film: a dev client
  quick-plays the gametest world, forces the chance to certain, sets the
  player to survival at one heart, deals a lethal blow through the real
  damage path, and photographs the blessing, the visitor from in front and
  behind, and his ascent until he is gone, into
  `run/booth/screenshots/booth-*.png`. It quits when done. Leave it alone
  while it runs: any input becomes part of the photos.
